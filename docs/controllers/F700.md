# F700

Alcor's F700 controller (AlcorMP family CTL-28, API `UfdApi_Gen`): an 8051 with a mask ROM,
a RAM overlay window for the boot firmware, and a NAND controller with hardware BCH ECC.
Values in code: `alcor/f700.py`. Mechanisms are described once in the generic docs; this
file has the F700's addresses and values.

Notation: `CODE:` mask ROM, `page0:` the always-resident firmware page, `ovN:` firmware
overlay N, XDATA addresses bare, `INTMEM` internal RAM, `bit 0x65` a bit address.

## Identity

| state | USB ID | INQUIRY |
|---|---|---|
| normal | from the config block (AlcorMP default `058F:6387`) | from the config block, revision rewritten by UFDMode |
| locked, no valid config | `058F:9380` | `Generic USB Flash Disk  7.76` |
| ROM mode | `058F:1234` | `Generic USB Flash Disk  7.76` |

`9A` chip ID `F7 00`, built from constants in the mask ROM. AlcorMP data tree:
`firmware/Gen/28/`.

## Supported NAND

| flash ID | part | FlashList record | boot firmware |
|---|---|---|---|
| `2C 84 44 32 AA 04` | Micron MT29F128G08CBCDB | 563 | `36_L04A_CB.BIN` |
| `2C 84 C4 34 AA 00` | Micron MT29F128G08CBCDB | 564 | `36_L04A_CB.BIN` |

Both records name boot module `10_L04A` and differ only in the flash ID. Other parts
resolve through their record's boot module token, untested. The die is Micron's 32-layer
3D MLC (L05B), 128 Gbit, 1 CE; the name is AlcorMP's label, public lists call it
MT29F128G08CBCEB.

ONFI parameter page of the first part:

| field | value |
|---|---|
| manufacturer, model | `SPECTEK`, `FxxL05B128G1KDBABJ4`, JEDEC `2C` |
| page | 16384 + 2208 B, 512 pages per block, 2192 blocks, 1 LUN |
| cells | 2 bits; endurance 1000 cycles; at most 96 bad blocks; block 0 guaranteed |
| planes | 2 plane-address bits (4 planes), the lowest block-address bits |
| ECC | in the extended parameter page (not read) |
| timing | tR 78 µs, tPROG 3 ms, tBERS 30 ms |

## Geometry and FTL parameters

| field | value |
|---|---|
| page | 16384 B (32 × 512-B sectors) + 2208 B spare = 18592 B raw |
| block | 512 pages MLC; 256 pages on the pseudo-SLC FTL system blocks |
| blocks | 2192 (`0x890`) per CE: 2048 + 144 spare |
| block address span | `0x1000` |
| ECC, data pages | BCH t = 78 (`0x4E`), 1-KB codewords, 1162-B frames, 16 per page; t = 72 (`0x48`) with 1152-B frames for the address march and boundary loop B |
| ECC, system pages | 512-B codewords, 650-B frames, 28 per page |
| ECC record | `ecc_params.tsv` key `00 04 02 4E` |
| FTL lanes | 4: block mod 4, 548 blocks each; a lane is a plane (?) |
| superblock stride | `0xF4` blocks |
| FTL units | 8 units × 4 cell slices |
| NAND attribute | `DA` (anchor byte `0x2E`, page pointers) |
| capacity, clean die | lane counts 487/498/491/502 → `0x01EE8000` sectors, about 16.6 GB |

Block layout: the F700 column of [nand.md](../nand.md#block-layout).

## Memory map

### CODE

| range | contents |
|---|---|
| `0x0000-0x6FFF` | mask ROM: USB, SCSI and vendor switches, `FA` handlers, lock gate, boot, default identity |
| `0x7000-0x7FFF` | RAM that differs per dump, not the XDATA at the same addresses (unknown) |
| `0xC000-0xCFFF` | boot firmware page 0, always resident; in MP mode the first half of the RAM loader |
| `0xD000-0xDFFF` | the resident overlay; index at `0xDFFC`, `55 AA` at `0xDFFE`; in MP mode the loader's second half |
| `0xC000-0xC05C` | hook table: 31 `LJMP` slots, slot n at `0xC000 + 3n` |
| `0x8000-0xBFFF`, `0xE000-0xFFFF` | mirrors of `0xC000-0xDFFF`; the code calls through them |

| `0x0400-0x05FF` | reply buffer: the `9A` reply and the `96` record are built here |
| `0x1000-0x10FF` | NAND page buffer window (?) |
| `0x2800-0x29FF` | controller state table (?) |
| `0x3C51`, `0x3CAC` | overlay copy mask; `EE` = the copy failed to read |
| `0x4102-0x4107`, `0x4400-0x4401` | USB device controller and endpoint registers (?) |
| `0x5000-0x51FF` | mount buffer: info record, then config block |
| `0x7000` | anchor record copy |
| `0x7014` | ROM read descriptors, 12 B each |
| `0x7100-0x71FF` | NAND set-up block (`0x71F0-0x71FF` geometry fields, `0x7191`, `0x7195`, `0x71A8`, `0x71B0`) |
| `0x7202`, `0x7205` | state flags (?) |
| `0x7206-0x7207` | logical block ID of the info record page (from CODE `CF88`: `00 04`), `07FF` = none |
| `0x7210-0x7211` | `A5 5A`: NAND parameter magic, set at mount |
| `0x7218`, `0x721A` | record sectors 2 and 3 results (`B0` = set) |
| `0x721C` | 2 when the first CBW tag was `05 8F 93 84`, else 7 |
| `0x7268`-`0x727C` | info record values: `7268` F1, `726C` F2, `7270` F3, `7274` F6, `7278` F4, `727C` F5 |
| `0x72C2 + 2i` | usable blocks of lane i (from the `99` record) |
| `0x73CA-0x73CB` | physical block of the info record page, `FFFF` = none |
| `0x7970` | firmware page slot table |
| `0x7A00-0x7AFF` | free-block list, from the data superblock head page |
| `0x7B00 + 16·lane` | per-lane allocation bitmap |
| `0x8000-0x80FF` | [NAND controller](#nand-controller-registers), mirrored at `0x8100` |
| `0x8040`, `0x8060`, `0x8094`, `0x801D` | `8040` bit 0 set by patch `0x19F` = `'Q'` with `FA 1D`; `8060 = 1` by sub `95`; `8094`, `801D` cleared at init (?) |
| `0x9009`, `0x900A`, `0x9012`-`0x9030` | peripherals: `900A` bit 7 = write-protect switch; `9012.0` clear and `9030.0` set for the mount; `9013 = 82`, `9020 = 2` at init; `9016` bit 7, `9017` bit 6 polled (?) |
| `0xA000-0xBFFF` | the overlay window as data: uploads and the boot copy code here |

### Internal RAM and bits

| address | contents |
|---|---|
| `0x15` | CE of the current `FA 0B`, during the slot-4 call |
| `0x31:32` | physical block of the info record page |
| `0x80`, `0x85`, `0x89` | Bulk-Only state; CSW tag; residue |
| `0x95` | CDB byte 3 of an `FA` command: CE, or the `FA 0A` sector count |
| `0x99` | LUN selector: 1 flash, 2, 4, `0x80` |
| `0x9A` | status: bit 0 parameter magic valid (gate input), bit 1 policy write-protect, bit 2 second protection bit, bit 4 cleared on `9016.1`, bit 5 NAND scan exhausted, bit 7 enforcement latch |
| `0x9B` | per-LUN write-protect mask, `FF` at reset: protected when `9B & 99` ≠ 0 |
| `0x9C` | second write-protect mask, 0 at reset |
| `0x9F:A0`, `0xA1` | selected lane's block count; lane |
| `0xAD` | CE limit from the patch window |
| `0xC2` | free-list count |
| bit `0x52`, `0x53` | a vendor command passed the gate |
| bit `0x5B` | mount failed |
| bit `0x63`-`0x67` | UFDMode flags from the record (`0x65` is the lock gate) |
| bit `0x69`, `0x6D` | slot 10 before every command; an upload has run |

## NAND controller registers

| register | use |
|---|---|
| `0x8000` | command cycle |
| `0x8001` | address cycle |
| `0x8002`, `0x8003` | data byte, channel 0 and 1 |
| `0x8004` | write 1: clock one byte from the NAND into `0x8002` |
| `0x8005` | bit 7 ready, bit 0 transfer done (once per ECC frame) |
| `0x8006` | transfer engine: `00` read the next ECC frame, `84` stream USB to NAND, `E0` after a reset |
| `0x8007` | CE mask: CE n via the table `40 80 10 20 04 08 01 02` |
| `0x800A` | channel mode, bit 0 = two channels; `14` on F700 |
| `0x800B` | mode: 1 → `00`, 2 → `20`, 4, 8, `0x10` → `40`; `40` on F700 |
| `0x8009`, `0x8011` | modes the loaders save, set to `AC`/`00` and restore |
| `0x8014` | XDATA page the engine writes a frame to |
| `0x8016`, `0x8017` | USB-to-NAND stream engine: start `C0`, count |
| `0x801A` | flags: bit 4 `FC` vs `FF` reset command, bit 7 load the descrambler seed |
| `0x8062`-`0x8065`, `0x8092` | descrambler seed |
| `0x8067` | bit 0: the last frame failed ECC |
| `0x8005`, `0x800C`, `0x8020-0x8021` | change by themselves (live status) |

Example: the raw read of block 0 page 2 from [commands.md](../commands.md#nand-commands),
as the probe loader drives it through these registers:

```
8007 ← 40               select CE 0 (CE mask table entry 0)
wait 8005 bit 7         controller ready
8000 ← DA               command cycle: SLC mode
8000 ← 00               command cycle: page read
8001 ← 00, 00           address cycles: column 0
8001 ← 02, 00, 00       address cycles: row 2
8000 ← 30               command cycle: confirm
8000 ← 70               status ...
8004 ← 1, read 8002     ... clock one byte out, repeat until bit 6 (ready)
8000 ← 00               back to data output
8004 ← 1, read 8002     one data byte; repeated for all 18592
```

With ECC, the transfer engine moves whole frames instead of single bytes:

```
8014 ← 50               the frame goes to XDATA 0x5000
8006 ← 00               start the engine: one ECC frame
wait 8005 bit 0         frame done
8067 bit 0              1 = the frame failed ECC
```

Read this way by the tool's loader, the same page comes back different on every read: the
descrambler state runs on and is not reseeded by the seed registers (unknown). The tool
reads raw.

The mask ROM reads its boot pages from 12-byte read descriptors at `0x7014`: byte 0 low
nibble `C` = valid, byte 1 high nibble = CE, byte 2 = cycle count, byte 3 = which cycles are
commands (bit set), then the cycles themselves. Block 0 page 2:

```
DA 00                   commands: SLC mode, page read
00 00 02 00 00          address: column 0, row 2
30                      command: confirm
```

## RAM loaders

AlcorMP's images in `SCAN_BIN/`. The upload is the image's first 9216 B with the 818-B patch
at `0x2000`. Subs are the ones AlcorMP sends under each; others may time out.

| role | image | subs |
|---|---|---|
| `rwfw` | `28_LB_RWFW.BIN` | `01 06 08 09 11 18 1E 1F 3E 45 46 94 96` |
| `sort` | `28_LB_SORT_3D.BIN` | `01 03 06 11 18 19 3A 42 43 47 94 96 99 9B` |
| `bct` | `28_LB_BCT.BIN` | `01 03 06 11 90 91 92 94 96 99 9A AE AF` |
| `scan` | `28_LB_SCAN_TOS_3D.BIN` | `01 03 04 05 06 11 94 96 97 99 A0 A1 A2 B0 B1` |
| `scan_rd` | `28_LB_SCAN_TOS_READ_N.BIN` | `01 03 04 06 94 96 99 C0 C1` |
| `scan_n` | `28_LB_SCAN_N.BIN` | `01 04 06 A7` |
| `hlf` | `28_LB_HLF.BIN` | `01 06 21 22` |

Slot 4 of every loader is the same switch on the sub, cases `02 03 04 05 06 0C 0D 95 96`;
how the other subs are reached is (unknown). Slots 0-7, 14, 15, 19, 22 and 24 hold code in
every loader; slots 2, 3, 7, 19 and 22 return `80`, `1`, `1`, `0`, `1`.

## Firmware routines

### Boot and overlays

| address | role |
|---|---|
| `CODE:4506` | reset-init: `9B = FF`, `9C = 0`, clears bit `0x65` |
| `CODE:08A8` | NAND init: reset, READ ID, read descriptors |
| `CODE:45F1` | apply the NAND set-up block |
| `CODE:0B9E-1014`, `CODE:2727` | boot: read block 0 pages 2 and 3, then `LCALL C000`; page read interpreter |
| `CODE:677A` → `492A` → hook `C039` | reset path into the mount |
| `CODE:5D2B`, `page0:C555` | overlay loader (bit 7 of R7 forces a reload); overlay copy select |
| `page0:C478` | NAND read with ECC; `EE` = uncorrectable |
| `page0:C188` | read firmware 4-KB block n |
| `CODE:636A` | select the first lane with usable blocks |
| hook `C003` → `D1AF`, `page0:C06F` | overlay 6 work; reset of the lane tables (overlay 0 `D83C`) |

### Mount and info record page

| address | role |
|---|---|
| `ov8:FDCD` (+ `FA2A`, `FBA6`) | cold boot: find the block tagged `07FC` |
| `ov0:D637` | reset path: clears the info record page pointer (`73CA`, `7206`) |
| `ov5:AAAF` | load the free list from the data superblock head: `0x700` → `0x7A00`, `0x36E` → count `INTMEM C2`, `0x37A` → `0x724C`, `0x3A0` → `0x3B70` |
| `page0:C12A` | take a block from a lane's free list |
| `ov8:D400` | mount: read sector 0 into `0x5000`, copy the values, set the flag bits |
| `ov8:D51F` | OR record byte `0x2E` into `INTMEM 9A`; read sectors 1, 2, 3, 7 |
| `ov8:D66B`, `ov8:D6D3` | defaults; failure exit (bit `0x5B`) |
| `CODE:49E3` | validate the config block |
| `CODE:3967` | `96`: build the record in `0x0400`, then hook slot 18 `C036` → `D211` → `ov7:F650` |
| `ov7:F650` | save sector R7 of the info record page |
| `ov7:E68A` | move the info record page to a fresh block (erase `CF8A`, tag `CODE:006F`, program `CA23`, release `D237`) |
| `CODE:66E9` | `81`: save a sector |
| `CODE:6412`, `CODE:679D` | `9B`, `9C` |

Where the mount puts the info record (read into `0x5000`, so record offset n is at `0x5000 + n`):

| record | RAM | field |
|---|---|---|
| `0x0A` | `7268` | `F1` total capacity |
| `0x11` | `726C` | `F2` second area |
| `0x16` | `7270` | `F3` |
| `0x1B` | `7278` | `F4` LBA bound |
| `0x21` | `727C` | `F5` refused-area bound |
| `0x26` | `7274` | `F6` flash LUN capacity |
| `0x2E` | `INTMEM 9A` (ORed) | write-protect |
| `0x30`-`0x48` | bits `0x50`-`0x70` | one flag bit per option byte (`0x3A` → bit `0x65`, the lock gate) |

| address | role |
|---|---|
| `CODE:04BA` | USB control-request switch (descriptors) |
| `CODE:3125`, `CODE:3182-31B2` | CBW handling: CDB length never read; first-command tag check |

| `CODE:2B14` | vendor switch (`FA` → `2C69`, `96` → `2BE9`) |
| `CODE:1480` | `FA` CDB parse: byte 3 → `INTMEM 95`, bytes 4-5, 6-7 |
| `CODE:14B3` | `FA` second switch (`0B` → `1607` → `6589`, `0E` → `161B`, `10` → `1781`) |
| `CODE:2E15` | `FA 0A` upload: code sectors to `0xA000`, patch window applied, NAND controller reset unless CDB byte 2 is 1 or 2, slot 0 |
| `CODE:6589` | `FA 0B`: CE check, `LCALL C00C` (slot 4); result `81` → the loader finished the transaction |
| `CODE:16B7`, `CODE:1781` | `FA 13` XDATA page, `FA 10` CODE read |
| `CODE:66C2` | send one 512-B data-in sector from `0x0000` |
| `CODE:4B45`, `CODE:5768` | Bulk-Only state machine: 3 passing CSW, 4 failing, 1 wait for the next CBW |
| `CODE:1F30` (thunk `0030`) | inline switch: `{target, value}` triples after the call, `0000`, default; also the SCSI switch |
| `CODE:2F9F`, `CODE:4BD2`, `CODE:2CB9` | slot 0 after an upload; slot 10 in the idle loop; slot 10 before each command |
| `CODE:5BDB` | write path: `9A.7` forces `9B |= F6` |

## Format values

### Blocks

| item | value |
|---|---|
| FTL system block, mirror | `0x000`, `0x0B2` (mirror anchor at page `0x88`) |
| scratch block | `0x058` |
| housekeeping block | `0x400` |

### Stages

Each param carries its stage's bytes on top of the base block; each loader its stage's
edits. Byte tables: `f700.STAGES`, `PARAM_BASE`, `PARAM_TOKENS`, `LOADER_EDITS`.

| stage | param bytes | loader edits | ECC t |
|---|---|---|---|
| enable | — | — | `4E` |
| scratch | `7A=00` | — | `4E` |
| ftl | + unit count | — | `4E` |
| march | + `3A=11`, `4F=1e` | — | `48` |
| march_end | the same | — | `4E` |
| sweeps | the same | housekeeping | `4E` |
| tables | + `6F=00` | housekeeping | `4E` |
| tail | + `11=10` | fw | `4E` |
| final | as tables | — | `4E` |

### Regions

`FA 0B` CDB bytes 10-13:

| bytes | used for |
|---|---|
| `00 00 00 00` | default |
| `01 00 00 00` | FTL unit build A columns |
| `FF FF 00 00` | system and firmware area |
| `01 5A 00 00` | data, FTL pre-pass |
| `FF FF 01 00` | firmware copy pages (scrambled) |
| `00 00 01 00` | scratch block |
| `FF FF 00 01` | `45` system records and anchors |
| `FF FF 20 02` | `45` anchor placeholder; `46` system area read |
| `04 00 00 00` | `22` housekeeping read-back |
| `00 00 01 5A` | `c1` read sweep |

### Timing

A full format (`--bad-blocks full --verify full`, about 30.5k ops) takes about an hour:

| ops | count | each | total |
|---|---|---|---|
| `b1` sweep | 140 | 7.3 s | 17 min |
| `c1` sweep | 548 | 1.4 s | 13 min |
| `b0` sweep | 140 | 4.0 s | 9 min |
| `c0` sweep | 276 | 1.4 s | 6 min |
| `43`, `9a`, `9b`, `42`, `47` scans | ~530 | 0.25-0.5 s | 3.5 min |
| everything else | ~28k | ~5 ms | ~4 min |

The defaults (`--bad-blocks quick --verify none`) send about 17k ops. A firmware-only update
is about 1.2k.
